# 05. 게임 엔진·테스트·배포 — Phaser 게임 코드, 자동 테스트, 플레이 링크

> **대표님용 요약**
> - 서리마을은 **Phaser 3.90**(무료 웹 게임 엔진)으로 만든 웹 게임이에요. 설치나 변환 과정 없이 파일 그대로 브라우저에서 돌아가고, 코드는 약 6,600줄(파일 36개)이에요.
> - 대표님이 직접 고칠 수 있는 파일은 세 개예요. `balance.js`(가격·속도 같은 숫자), `world.js`(지도 배치), `strings.js`(게임 안 글자)예요. 숫자를 잘못 적어도 게임이 안전한 값으로 바꿔서 계속 돌아가요.
> - 테스트는 **로봇이 화면 없는 크롬으로 직접 게임을 해 보는 방식**이에요. 한 번 끝까지 하는 데 약 10~12분 걸리고 스크린샷 25장이 나와요. 시간을 빠르게 돌리면 실제 24분 분량을 45초 만에 플레이해서 밸런스를 잴 수 있어요.
> - 배포는 두 가지예요. 하나는 **GitHub Pages**(고정 주소)이고, 다른 하나는 **Claude 아티팩트**(플레이 링크)예요. 아티팩트에 올리는 묶음은 명령 한 줄이면 만들어지고, 실제 호스팅 환경을 흉내 낸 테스트로 확인해요.
> - 새 세틀러식 게임에도 **그림 불러오기, 소리, 저장, 이펙트, 테스트, 배포 도구는 거의 그대로** 쓸 수 있어요. 일꾼 수백 명이 길을 따라 물건을 나르는 부분은 새로 설계해야 해요. 권장 설계는 이 문서 13장에 정리해 두었어요.

이 문서는 새 프로젝트의 Claude 세션이 정확히 따라 할 수 있도록 **실제 코드·스크립트를 읽고 확인한 내용만** 적었습니다.
경로는 전작 기준 `frost-village/`(이사 키트 안에서는 `reference/frost-village/`)입니다. 명령은 모두 **게임 루트 폴더에서** 실행합니다(예: `cd frost-village`).
확인하지 못한 내용은 "미검증"이라고 표시했습니다.

## 목차
0. 한눈에 보기 (폴더·크기·실행 흐름)
1. `index.html` 과 `src/main.js` — 시작, 화면 크기, 오류 안내
2. `src/core/` — 엔진 기반 모듈 (Assets, Placeholders, Audio, Input, Iso, Save, View, Panel)

4. `src/scenes/` — Boot → Preload → Title → Game + UI
5. `src/entities/` — 캐릭터·일꾼·가공소·판매처
6. `src/systems/` — Ground, DepthSort, Collision, Economy, Progression, Tutorial, Effects
7. `src/data/` — 기획자가 고치는 파일 (balance / world / strings)
8. 테스트 훅 `window.__FV` 와 `?debug=1`
9. `tools/test/` — 자동 테스트 사용법 (정확한 명령)
10. `tools/build/` — 아티팩트 묶음 만들기와 배포 테스트
11. 배포: GitHub Pages 와 Claude 아티팩트 제약
12. 새 프로젝트에서 재사용하는 법 (복사 목록, 바꿀 곳, 추가 레시피)
13. 세틀러식 게임 권장 아키텍처 (같은 도구 기반)
14. 빠른 참조

```
frost-village/

  manifest.webmanifest    PWA 정보(이름, 세로 고정, 아이콘 = portrait_player_512/128)
  lib/phaser.min.js       Phaser 3.90.0 (전역 `Phaser`, VERSION:"3.90.0" 확인) + PHASER_LICENSE.md
  src/                    ES 모듈 36개, 약 6,600줄 — 빌드 단계 없음, 런타임 npm 의존성 없음

    systems/              Ground, DepthSort, Collision, Economy, Progression, Tutorial, Effects
    data/                 balance.js, balanceCheck.js, world.js, strings.js            ← 기획자 편집
  assets/<폴더>/manifest.json + 아틀라스/이미지/소리 (24 MB: villagers 9.9, audio 4.9, characters 3.6, props 2.3, ...)
  tools/test/             serve, pw, smoke, shot, soak + review_* 검수 스크립트
```

**실행 흐름**: `index.html` → `lib/phaser.min.js` → `src/main.js` → 장면 `Boot → Preload → Title → Game (+ UI 를 위에 겹쳐 실행)`.
- 그림·소리는 전부 `assets/*/manifest.json`을 통해서만 찾습니다(`core/Assets.js`). 그림 파일이 없으면 **자동으로 대체 그림**을 그려서 게임이 멈추지 않습니다. 그래서 전작에서는 코드 팀이 그림 팀을 기다리지 않고 동시에 일할 수 있었습니다.
- 숫자는 `src/data/balance.js`, 배치는 `src/data/world.js`, 글자는 `src/data/strings.js` 한 곳에만 둡니다.

## 1. `index.html` 과 `src/main.js`

### 1.1 `index.html` (120줄)
- 스타일: 전체 화면 고정, 스크롤·확대·텍스트 선택 끔(`touch-action: none`, `user-select: none`), 배경 그라데이션.
- `#fv-loading` 로딩 문구(Preload 장면이 지움), `#fv-rotate` 가로로 든 휴대폰에서 "세로로 돌려 주세요" 안내(CSS media query: `orientation: landscape and max-height: 500px and pointer: coarse`), `#fv-error` 오류 카드.
- **오류 안내 스크립트**(코딩 모르는 사람용 친절한 메시지):
  - `window.__FV_SHOW_ERROR(msg, detail, crash)` — 카드 표시. `crash=true` 면 "처음부터 하기" 버튼이 생깁니다. 이 버튼은 `window.__FV_NO_SAVE = true` 로 설정한 뒤 저장 `frostVillage.save.v1` 을 `.bad` 로 옮기고 새로고침합니다.
  - `file://` 로 열면 "더블클릭으로는 안 열려요" 안내.
  - 부팅 전 스크립트 로드 실패 → "불러오지 못했어요". 부팅 후에는 **게임 루프가 실제로 멈췄을 때만**(1.5초 동안 `game.loop.frame` 이 그대로) "멈췄어요" 카드를 띄웁니다.
  - 20초 안에 `window.__FV_BOOTED` 가 없으면 → "파일을 불러오지 못했어요"(샌드박스 iframe 에서 모듈이 막힌 경우).
- 스크립트 순서: `<script src="lib/phaser.min.js">` → `<script type="module" src="src/main.js">`. **모든 경로가 상대 경로**라서 어느 하위 주소에서도 돌아갑니다(GitHub Pages `/nurient/frost-village/`).

### 1.2 `src/main.js` (104줄)
- **논리 화면 크기**: 가로 720 고정, 세로는 기기 비율에 따라 1280~1600 (`logicalHeight()`). `Scale.FIT` + `CENTER_BOTH`. 키가 큰 폰은 위아래 띠 없이 채워집니다.
- **선명도(렌더 배율) `View.k`**: 캔버스를 `720×H` 의 k배로 그립니다. `k = clamp(round(cssW*dpr/720 *20)/20, 1, MAX_RENDER_SCALE=2)`. 모든 카메라는 줌에 k를 곱합니다(`View.applyUI(cam)` 또는 `cam.setZoom(zoom*View.k)`).
- 안전 영역(노치): CSS 변수 `--sat/--sab`(env(safe-area-inset-*)) → `View.safeTop/safeBottom`(논리 px).
- Phaser 설정 핵심: `type: Phaser.AUTO`(WebGL, 안 되면 Canvas), `input.activePointers: 3`, `fps.target: 60`, `disableContextMenu`, `scene: [Boot, Preload, Title, Game, UI]`.
- `checkBalance()`(data/balanceCheck.js) 를 게임 생성 **전에** 실행 → balance.js 의 잘못된 값 자동 보정.
- `?debug=1` → `window.__FV_DEBUG = true`.
- 화면 회전/크기 변경: 120ms 디바운스 후 `View` 재계산 → `game.scale.setGameSize()` + `refresh()`.
- **약한 GPU 자동 대응**: 3초마다 확인. 마을 장면이 돌아가는 중이고 `View.k > 1.05` 인데 `actualFps < 30` 이면 `View.forceK = 1`(이번 세션은 1배로).
- **120/144Hz 화면**: 4초 뒤 `actualFps > 100` 이면 루프를 80fps로 제한(배터리 절약). 60/90Hz는 그대로.
- 최소 테스트 훅: `window.__FV = { game }`(Game 장면이 전체 훅으로 확장), `window.__FV_BOOTED = true`.

### 1.3 `src/core/View.js` (24줄)
`View = { W:720, H, k, forceK, safeTop, safeBottom, applyUI(cam), toLogical(v) }`. 포인터 좌표(캔버스 px)를 논리 px로 바꿀 때 `View.toLogical`.

## 2. `src/core/` — 엔진 기반 모듈

### 2.1 `Assets.js` (268줄) — 매니페스트 레지스트리 + 대체 그림
| API | 하는 일 |
|---|---|
| `FRAGMENTS` | 불러올 에셋 폴더 목록. **현재 `['characters','props','fx','ui','ground','audio']`** (3.4 주의 참고). `build_artifact.mjs` 도 이 줄을 정규식으로 읽어서 묶을 폴더를 정합니다 |
| `queueManifests(load)` | `assets/<f>/manifest.json` 을 `manifest_<f>` 키로 큐 |
| `mergeManifests(jsonCache)` | 조각들을 `Assets.m` 하나로 합침: `atlases/images/spritesheets`(배열, key로) + `characters/sprites/nineSlice/audio/audioGroups`(객체 병합, 뒤 조각이 덮어씀). 없는 조각은 건너뜀(`Assets.fragments[f] = false`) |
| `queueAssets(load, {audio, musicFilter})` | 아틀라스·이미지·스프라이트시트·오디오를 Phaser 로더에 큐. 경로 = `'assets/' + 매니페스트 경로` |
| `queueAudio(load, filter)` | 오디오 하나에 파일 여러 개(ogg, mp3) — 브라우저가 고름 |
| `isDeferredAudio(key)` | `/^(bgm_village|amb_)/` — 마을 음악·환경음은 **타이틀 뒤 Game 장면에서** 늦게 불러옴(첫 화면 빨리) |
| `onLoadError(file, load)` | Phaser는 첫 형식(ogg)이 실패하면 다음(mp3)을 시도하지 않음 → **나머지 URL로 한 번 재시도**. 그래도 실패하면 `failed` 에 기록 |
| `finalize(game)` | 로드 완료 후 애니메이션 생성: 스프라이트시트(키 = 시트 키), 스프라이트 애니(`spr:<key>:<anim>`), 캐릭터(`<char>:<anim>:<dir>`), 그리고 생성 텍스처 `fv_shadow`, `fv_white` |
| `charDef(key)` | `COMMON_CHAR` ← `CHAR_DEFAULTS[key]` ← 매니페스트 `characters[key]` 순으로 병합(애니는 따로 병합). 캐시됨 |
| `buildCharacter(game, key)` | 각 애니 × `def.dirs` 마다 프레임 이름 템플릿 `{anim}_{dir}_{i}` 로 아틀라스에서 찾음. 없으면 대체 캐릭터 텍스처 `ph_char_<key>`(2프레임, fps 4) + 경고 1회 |
| `charAnim(key, anim, baseDir)` | 애니 키 반환 + 대체: `carry_idle→idle, carry_walk→walk, happy/work/chop/mine/harvest→idle`, 최후 `<key>:idle:S` |
| `sprite(key)` | 정지 그림 해석 → `{tex, frame, anchor, def, ph}`. 순서: ① `sprites[key]` 의 atlas+frame ② `sprites[key].image` ③ 같은 키의 텍스처(images) ④ 대체 그림 `ph__<key>` + `console.warn('[FrostVillage] missing asset → placeholder:', key)` (키마다 1회). 결과 캐시 |
| `has(key)`, `def(key)` | 진짜 그림이 있는지 / 매니페스트 정의(footprint, stackStep, fxPoints …) |
| `image(scene,x,y,key)`, `apply(img,key)` | 그림 만들기 / 기존 이미지에 키 적용(원점 = anchor 자동) |
| `source(key)` | Canvas2D 굽기용 원본 이미지+프레임(Ground.js 가 사용) |
| `sheet(key)`, `sheetDef(key)`, `spriteAnim(key, anim)` | 애니 키가 있으면 반환, 없으면 null |
| `nine(key)` | 9-slice 여백(`nineSlice[key]`), 없으면 그림 크기의 1/3 |
| `audioDef(key)`, `audioGroup(key)` | 오디오 정의 / 변형 묶음 |
| `warned`, `failed` | 대체 그림이 쓰인 키 목록(테스트 훅 `warnings()` 로 확인) |

`CHAR_DEFAULTS` 에는 전작 캐릭터 11종의 기본 애니 정의가 코드로 들어 있습니다(아틀라스가 없을 때도 같은 애니 키가 생기게 하려는 용도). 새 게임에서는 새 캐릭터 기본값으로 바꾸거나 비워도 됩니다(매니페스트가 있으면 매니페스트가 우선).
`COMMON_CHAR` = `frameSize [128,128], anchor [0.5,0.8125], dirs S/SE/E/NE/N, mirror, frameName '{anim}_{dir}_{i}', shadow [46,18], headTop -84, kind 'human', carryPoint{...}` — 계약서(CONTRACT §3)와 같습니다.

### 2.2 `Placeholders.js` (405줄) — 그림이 없어도 돌아가게
- `Placeholders.sprite(textures, key, def)`: 키 접두어로 종류를 추측(`item_`, `station_`, `ui_`, `fx_`, 건물…) → 캔버스로 그럴듯한 대체 그림(아이템 = 색 원, 건물 = 상자, UI = 둥근 패널 등). `ITEM_COLORS`, `CHAR_COLORS` 표에 키별 색.
- `character(textures, key, dirs)`: 캡슐 몸 + 코(방향 표시) 2프레임 × 방향.
- `shadow()` → `fv_shadow`(부드러운 타원 그림자), `white()` → `fv_white`.
- 그 밖에 내보내는 도우미: `rr, star, heart, diamond, rng(seed), hashStr`. `rng(seed)` 는 xorshift 결정적 난수(배치 재현용, Game/Ground 에서 사용) → **새 게임 시뮬레이션의 시드 난수로 재사용 가능**.

### 2.3 `Audio.js` (178줄)
| API | 내용 |
|---|---|
| `init(game)`, `start()` | `start()` 는 **첫 탭에서만**(Title) 호출 → `started = true` + 컨텍스트 resume. 그 전에는 모든 재생이 조용히 무시됨 |
| `resume()` | iOS 전화·앱 전환 후 멈춘 컨텍스트 재개. UI 장면이 모든 `pointerdown` 에서 호출 |
| `live` | 컨텍스트가 running 이고 잠김 해제일 때만 true (창이 비활성일 때 소리가 쌓였다가 한꺼번에 터지는 것 방지) |
| `play(key, {volume, rate, detune, throttle})` | 효과음. `audioGroups` 키면 무작위 변형(직전 것 피함). 키별 최소 간격 기본 35ms. 볼륨 = 매니페스트 `volume` × opts |
| `playMusic(key)` / `stopMusic(ms)` / `applyMusic()` | 배경음악(이전 곡 900ms 페이드아웃, 새 곡 1200ms 페이드인), 음악 켜고 끄기 반영 |
| `setAmbience(key, vol)` + `updateAmbience(dt)` | 환경음 루프 목표 볼륨, 매 프레임 부드럽게 따라감(Game.tick 에서 위치에 따라 바다·불 소리 조절) |
| `setSoundEnabled(on)`, `setMusicEnabled(on)` | `Settings` 에 저장 |
| `trimLoops()` | 루프 소리가 매니페스트 `duration` 보다 길게 해독되면(Safari mp3 앞 공백 등) 정확히 `[mp3StartPad, +duration)` 로 잘라 끊김 없는 루프. 매니페스트에 `loop, duration, mp3StartPad` 필요(문서 04) |
| `vibrate(ms)` | 소리가 켜져 있을 때만 진동 |

Game 장면의 `sfxAt(key, x, y, opts, force)` 는 **화면 안/근처일 때만** 재생하고 화면 밖 220px 이내면 볼륨을 절반으로 줄입니다(일꾼 소리 폭주 방지). 새 게임에서 일꾼 수백 명이면 반드시 이 방식을 쓰세요.

### 2.4 `Input.js` (76줄) — 떠다니는 조이스틱 + 키보드
- 화면 아무 데나 누르면 그 자리가 조이스틱 중심(`JOY_RADIUS = 78`), 멀리 끌면 중심이 손가락을 따라옴. 키보드 WASD·방향키(캡처해서 바깥 페이지가 스크롤되지 않음) + 스페이스 캡처.
- UI 장면이 `pointerDown/Move/Up` 을 넣어 주고, Game 장면이 매 프레임 `Input.update(now)` → `Input.vec {x, y, mag}` 를 읽음.
- 테스트용 `Input.override = {x, y}` (`__FV.setInput`), `release()`(창 비활성·페이지 숨김 시).
- 여러 손가락: 조이스틱 손가락을 떼면 다른 눌린 손가락이 이어받음(UI.js). `review_robust_multitouch.mjs` 로 검증.
- **세틀러식에는 조이스틱이 필요 없을 가능성이 큽니다**(아바타 없음 → 카메라 끌기·핀치 줌·탭 선택). 포인터 처리 방식만 참고하세요(13.11).

### 2.5 `Iso.js` (68줄) — 아이소 방향 수학 (계약서 §1·§9)
- `AX = {x:45.25, y:22.63}`(월드 X 1m), `AY = {x:45.25, y:-22.63}`(월드 Y 1m), `PPU = 64`.
- 8방향: `DIRS8 = ['E','SE','S','SW','W','NW','N','NE']`, 인덱스 = `round(atan2(vy*2, vx) / 45°) mod 8` (`dirFromVec`). y를 2배 하는 이유: 2:1 아이소에서 화면 속도를 바닥 방향으로 바꾸기 위해.
- `DIR_BASE[i]`, `DIR_FLIP[i]`: 렌더한 5방향 + 좌우 반전 표. **코드에 고정된 표**(`BASE`)이고, 매니페스트의 `mirror` 필드는 읽지 않습니다 → 8방향을 모두 렌더하면 이 표를 바꿔야 합니다(3.4).
- `isoPt(cx,cy,mx,my)`, `isoInv(dx,dy)`, `isoRect(cx,cy,w,h)`(마름모 네 꼭짓점), `inIsoRect(...)`, `gdist/gdist2`(바닥 거리: y×2), `dirTo(a→b)`.

### 2.6 `Save.js` (133줄) — 저장(절대 게임을 망가뜨리지 않게)
- 키: `SAVE_KEY = 'frostVillage.save.v1'`, `SETTINGS_KEY = 'frostVillage.settings.v1'`, `BACKUP_KEY = 'frostVillage.save.backup'`, `BAD_KEY = 'frostVillage.save.v1.bad'`.
- `readJSON/writeJSON/removeKey`: **모든 localStorage 접근을 try/catch**(비공개 창, 샌드박스 iframe, 용량 초과). `getStore()` 자체도 try/catch(접근만 해도 예외가 나는 환경이 있음).
- `sanitizeSave(raw)`: 불러온 값을 전부 검사 — 숫자는 유한·범위 안, 목록은 목록, **모르는 아이템 종류는 버림**(`ITEMS` 화이트리스트, `FOODS`, `GOODS`). 새 아이템을 추가하면 여기도 추가해야 저장이 됩니다.
- 버전: `SAVE_VERSION = 1`, `MIGRATE[v]`(v → v+1 변환 함수 표, 지금은 비어 있음). 모르는 버전이면 `BACKUP_KEY` 에 한 번 복사해 두고 새로 시작.
- `Save.load() / write(state) / clear() / quarantine()`(게임을 망가뜨린 저장을 `.bad` 로 옮김), `lastWriteOk`. `write` 는 `window.__FV_NO_SAVE` 이면 쓰지 않음.
- `Settings = { data: {sound, music, lang}, load(), save() }`.
- 저장 시점: 5초마다(`BALANCE.autosaveEvery`), `visibilitychange`(숨김), `pagehide`, 그리고 해금·업그레이드 직후. 저장 실패 시 "이 환경에서는 진행 상황이 저장되지 않아요" 토스트 1회.

### 2.7 `Panel.js` (49줄)
`panel(scene, x, y, key, w, h)`: WebGL이면 Phaser `NineSlice`, **Canvas 렌더러(WebGL 막힘)면 둥근 사각형 대체품**(`FlatPanel`, 같은 API: `setSize/setOrigin/setTint`). Phaser NineSlice는 WebGL에서만 그려지기 때문입니다. `review_robust_platform.mjs` 의 Canvas 대체 검사로 확인했습니다.

### 3.3 대체 그림(placeholder) 원칙
- 매니페스트 조각이 통째로 없어도(404) 게임은 돌아갑니다. 테스트(`smoke.mjs`)는 조각 404를 "알림"으로만 보고 실패로 보지 않습니다.
- 대체 그림이 쓰이면 키당 `console.warn` 1회 + `__FV.warnings()` 목록에 남습니다. 배포 테스트(`test_deploy.mjs`)는 "no placeholder art" 단계에서 **대체 그림 0개**를 요구합니다.
- 새 프로젝트에서도 이 원칙을 유지하세요. 코드 팀이 그림을 기다리지 않아도 됩니다.

### 3.4 주의 — 확장 에셋 폴더는 아직 게임에 연결되지 않았음 (꼭 읽기)
작성 시점(2026-10-07) 코드 기준으로 확인한 사실입니다.
1. **`villagers`, `life_props`, `emotes` 폴더는 만들어져 있지만 로드되지 않습니다.** `FRAGMENTS` 에 6개만 있고, `src/` 어디에도 `npc_`, `emote_`, `snowman` 같은 키를 쓰지 않습니다. `build_artifact.mjs` 도 이 폴더들을 "not loaded by the game yet" 으로 빼고 묶습니다.
   - 연결하려면 `src/core/Assets.js` 의 `export const FRAGMENTS = [...]` 에 `'villagers', 'life_props', 'emotes'` 를 추가하세요. 이 줄은 **따옴표 문자열 배열 형태로 그대로 두어야** 빌드 스크립트의 정규식이 읽습니다.
   - 아티팩트 파일 수: 지금 168개. 여기에 villagers 61 + emotes 10 + life_props 3 을 더하면 약 242개로, 한도 255에 가깝습니다. 넘으면 빌드가 `.ogg` 41개를 빼고 mp3만 남깁니다(자동). 용량은 약 15 MB → 약 26 MB(한도 64 MB 안).
2. **애니메이션별 방향 목록(`anims[x].dirs`)을 코드가 무시합니다.** 주민의 사회적 애니(happy, talk, laugh, wave, surprised, angry, sad, throw, hit, dance, shiver, sit …)는 S/SE/E 3방향만 있습니다. 그런데 `buildCharacter` 는 `def.dirs`(5방향)를 모든 애니에 적용합니다. 그러면 NE/N 프레임을 못 찾아서 **대체 캐릭터 애니가 만들어지고 `def._placeholder = true` 가 됩니다**. 이 플래그 때문에 이후 만들어지는 그 캐릭터의 애니가 전부 fps 4로 바뀌고, 타격 프레임도 1번으로 바뀝니다.
   - 고칠 곳: `buildCharacter` 에서 `for (const dir of (a.dirs || def.dirs))` 로 돌리고, 프레임이 없는 방향은 대체 애니를 만들지 말고 건너뛰기. 그리고 `charAnim()` 에서 그 방향 애니가 없으면 계약서 규칙대로 "가장 가까운 S/SE/E(반전 포함)"로 돌려서 찾기. 이 경우 `Character.play()` 가 `flipX` 도 같이 맞춰야 합니다.
   - `charAnim()` 의 대체 표에는 `run, talk, laugh, wave, sit …` 이 없습니다. 필요한 대체(`run→walk`, 나머지→`idle`)를 추가하세요.
3. **8방향을 모두 렌더(반전 없이)하려면** `Iso.js` 의 `BASE` 표(SW→SE 반전 등)를 바꿔야 합니다. 코드는 매니페스트 `mirror` 를 읽지 않습니다. `COMMON_CHAR.dirs`/매니페스트 `dirs` 에 SW, W, NW 를 추가하고, `BASE` 를 `SW: ['SW', false]` 식으로 바꾸면 됩니다(문서 03 §10.4 와 짝).
4. 펫(`kind: 'pet'`)은 `Character.carryOffset()` 이 `kind !== 'animal'` 로만 거르기 때문에 머리 위에 짐을 올리는 사람 규칙을 탑니다. 펫에게 짐을 들리지 않으면 문제없습니다.

### `Game.js` 구조 (새 게임에 그대로 가져갈 패턴)
- `create()` 는 `build()` 를 try 로 감쌉니다. 저장 데이터 때문에 만들다 실패하면 **저장을 `quarantine()` 하고 `scene.restart({fresh:true})`** 합니다. 깨진 저장이 게임을 영원히 막지 못합니다.
- `update()` 는 `tick()` 을 try 로 감쌉니다. 오류는 콘솔에 1회만 남기고 루프는 계속 돕니다(Phaser 루프 안의 예외는 게임을 멈추기 때문).
- `tick(time, delta)`: `dt = min(0.05, delta/1000)` **가변 스텝**(고정 스텝 아님) → Input → ground → player → 발판 → 자원 노드 → 동물 → 가공소 → 판매처 → 일꾼 → 튜토리얼 → 가림막(occluder) → 카메라 목표 보간 → 눈 파티클 → 위치별 환경음 → 자동저장.
- `UIProxy`: Game에서 UI 장면 메서드를 부를 때 UI가 준비되지 않았으면 무시(`setCoins, coinFly, toast, banner, setObjective, celebrate`).
- `moveAgent(a, tx, ty, speed, dt, arrive)`: 직선 조향 + **모든 agent 와의 분리(O(n²))** + 정적 충돌 밀어내기 + 막히면 0.7초 옆걸음. 경로 찾기는 없습니다(지도를 길이 막히지 않게 배치하고, 일꾼은 7초 안에 못 가면 포기). **세틀러식에서는 이 방식을 그대로 쓰면 안 됩니다**(13.10의 측정 참고).
- 가림막(occluder): 키 큰 그림 뒤로 촌장이 가면 **실제 픽셀이 촌장을 덮을 때만** 반투명(`textures.getPixelAlpha` 로 2점 검사, 0.12초 간격).
- 구역 해금 연출 `revealZone`: 카메라 이동 → 바닥 페이드 → 물건들이 거리순으로 튀어나옴 → 펑 + 흔들림.
- 저장: `serialize()` → `Save.write()`. 날아가는 중인 아이템은 도착지 기준으로 저장(`ItemStack.inTypes`), 손님 줄은 저장하지 않음.

## 6. `src/systems/`

### 6.1 `Ground.js` (285줄) — 바닥 굽기
- 바다: `tileSprite`(`water_sea`) 스크롤 + 물고기 떼 2겹(`fish_school`, 다른 속도·투명도).
- 땅: **세로 1024px 청크(`CHUNK = 1024`)로 나눠 캔버스 텍스처 `fv_ground_<y0>` 에 한 번 굽기**. 굽는 순서: 얕은 물 띠 → 눈 패턴(`ctx.createPattern`) → 가장자리 푸른 음영 → 해안선(얼음 테두리 + `shore_foam` 띠를 곡선 따라 32px 조각으로 회전) → 길 → 데칼.
- **부드러운 길 기법**: 길 전체를 한 경로로 만들어 캔버스 밖(`OFF = 30000`px)에 그리고, 그 **그림자(`shadowBlur`)만 캔버스에 떨어지게** 합니다(`shadowOffsetX = OFF`). 그러면 모든 브라우저에서 가장자리가 부드럽고, 교차점이 진해지지 않습니다. 그 위에 눈 더미 데칼과 발자국 데칼(아이소 각 26.6°에 맞춰 회전)을 찍습니다. → **세틀러식 길 그리기에 그대로 쓸 수 있는 기법**입니다.
- 구역 바닥 `zoneFloor(id, z)`: 아이소 평행사변형을 별도 이미지 `fv_floor_<id>` 로 굽기(그림자, 안쪽 베벨, 눈 테두리, `floorAlpha` 로 눈과 섞기). 잠긴 구역은 알파 0 → 해금 때 페이드인.
- 도우미: `pattern(ctx, key, scale)`, `drawFrame(ctx, key, x, y, scale, rot, alpha)`(아틀라스 프레임을 캔버스에 찍기).
- 의존성: `WORLD`(data/world.js), `shoreY`(Collision.js) → 전작 지도에 묶여 있으니 **기법만 가져가서 새로 작성**하세요.
- 메모리(측정): 1800×2620 지도에서 굽기 청크 3장 ≈ 1.8+1.8+1.0 Mpx, 가장 큰 일반 텍스처는 `props_buildings` 2.9 Mpx(1980×1460). GPU에서는 1 Mpx ≈ 4 MB(RGBA)입니다.

### 6.2 `DepthSort.js` (39줄) — 그리기 순서 층
`DEPTH` 상수(아래가 먼저 그려짐): `WATER -20000, FISH -19900, WAVES -19800, GROUND -15000, FLOOR -14000, GROUND_DECAL -13500, OUTLINE -13000, PAD -12000, PAD_ITEM -11900, PAD_TEXT -11800, SHADOW -11000, DUST -10900,` (월드 물건 = 자기 y: 0 ~ 지도 높이) `FLY 30000, FX 31000, BUBBLE 40000, LABEL 41000, ARROW 45000, TOP 50000`.
- 실제 깊이 정렬은 **각 물건이 `setDepth(y)`** 하는 방식입니다(`Character.sync`, `staticImage`). `DepthSort` 클래스는 `Game` 에서 만들기만 하고 `update()` 를 부르지 않습니다(사용되지 않음).
- 지도 높이가 30000px을 넘으면 `FLY/FX` 상수와 겹치므로 상수를 키우세요.

### 6.3 `Collision.js` (84줄)
정적 장애물 = "바닥 공간"(y×2) 원. 균일 격자 `CELL = 160`px. `add(x,y,r,tag)`, `blocked(x,y,rad,ignore)`, `resolve(p, rad)`(밀어내기 + 지도 경계 + 해안선), `shoreY(x)` = `base + Σ amp·sin(x·freq+phase)`. → 칸 기반 세틀러식에서는 **칸마다 막힘 표시(typed array)** 로 대체(13.9).

### 6.4 `Economy.js` (24줄)
코인 `add(n, wx, wy, fly)`(HUD로 동전 날아가기) / `spend(n)`. 전작 전용.

### 6.5 `Progression.js` (186줄)
`STEPS` 표(id, type 'hire'|'zone', worker, zone, after, index, role)로 **데이터 기반 해금 순서**. 보이는 단계 = 아직 안 했고 선행 단계를 끝낸 것. `BENCH_AFTER`(업그레이드 작업대 등장), `COMPLETE_AFTER`(마을 완성 축하). 부분 결제(`paid`) 저장. → "데이터 표로 진행 순서 정하기" 패턴은 세틀러식 건물 해금·임무에 재사용 가능.

### 6.6 `Tutorial.js` (208줄)
월드 화살표 + 화면 밖 가장자리 화살표(UI.js). 우선순위: ① 살 수 있는 해금 발판 ② 가방이 꽉 참 → 놓을 곳(없으면 버리기) ③ 첫 업그레이드(한 번) ④ 새 구역 안내(최대 90초) ⑤ 3초 가만히 있으면 "다음에 할 일". → 화살표·가장자리 표시 코드는 재사용 가능, 판단 로직은 전작 전용.

### 6.7 `Effects.js` (177줄) — 손맛 (그대로 재사용)
- **풀(pool)**: 아이템 스프라이트(`takeItem(type)/releaseItem(s)`), 스프라이트시트 이펙트(`sheetPool`), 떠오르는 글자(`textPool`). 새로 만들지 않고 돌려 씀.
- 파티클 프리셋 `PRESETS`: `wood, leaf, snowhit, rock, spark, wheat, splash, dust, smoke, heart, star, confetti, coin, glow, ring, flame, snowfall` → `burst(name, x, y, qty)`, `emitter(name)`.
- `sheet(key, x, y, {size, depth})`: 한 번 재생(매니페스트가 `repeat:-1` 이어도). 시트가 없으면 파티클로 대체(`fx_poof → snowhit+glow` 등).
- `loop(key, x, y, size, depth)`: 반복 시트(불, 반짝이, 동전 회전).
- `floatText(x, y, text, color, size)`, `fly(spr, fx, fy, target|()=>target, {dur, height, scaleTo, spin, onDone})`: 포물선 비행(트윈 카운터), `shake`, `vibrate`, `pop(obj)`(찌그러졌다 튕기기).
- 주의: `fly` 는 아이템마다 트윈 하나입니다. 동시에 수백 개가 날면 트윈 비용이 커집니다 → 세틀러식의 깃발 사이 운반은 시뮬레이션 좌표로 그리세요(13.10).

## 10. `tools/build/` — 아티팩트 묶음과 배포 테스트

처음 한 번: `cd tools/build && npm install` (esbuild `^0.25.12` 를 `tools/build/node_modules` 에 설치. 몇 초). `package.json` 스크립트: `npm run artifact`, `npm run artifact:webp`, `npm run artifact:inline`(= `--inline --webp`), `npm test`(= test_deploy).

### 10.1 `build_artifact.mjs` (459줄)
```
node tools/build/build_artifact.mjs [--no-minify] [--mp3-only] [--inline] [--webp]
```
(경로는 스크립트 위치 기준이라 어느 폴더에서 실행해도 됩니다.)
- 출력 `dist/artifact/`:
  - `index.html` — **본문만 있는 페이지**(doctype/html/head/body 태그 없음, `<title>` 로 시작). 아티팩트 호스트가 뼈대를 씌우기 때문입니다. 안에 `<title>`, 어두운 밤하늘 스타일(`color-scheme: dark`, body 배경 직접 지정, `#game` 을 safe-area 만큼 띄움), 로딩·회전·오류 카드(index.html 과 같은 친절한 안내), `lib/phaser.min.js`, `game.js`.
  - `game.js` — `src/main.js` 와 import 하는 모든 모듈을 **esbuild 로 클래식 스크립트 하나(IIFE, ES2019, minify, `charset: 'ascii'` → 한글은 \u 이스케이프)** 로 묶음. ES 모듈·`import()`·모듈 워커 금지(빌드가 검사). 현재 178 KB.
  - `lib/`(phaser + 라이선스), `assets/`(**`FRAGMENTS` 에 있는 폴더만** 복사, 웹 형식만, `.py`·숨김 파일 등 제외).
  - `dist/artifact_files.json` — `{page, root, files[], note}` (아티팩트 도구에 넘길 파일 목록).
- 검사(문제가 있으면 exit 2): 파일 ≤ 255, 합계 ≤ 64 MB, 파일당 ≤ 16 MB, 매니페스트에 적힌 경로가 모두 존재, 절대 URL 없음, 페이지에 doctype/html/head/body 없음, `<title>` 로 시작, game.js 에 import/export 없음. 매니페스트에 없는데 복사된 파일도 알려 줌.
- **파일이 255개를 넘으면** 자동으로 `.ogg` 를 지우고 오디오 매니페스트를 mp3 전용으로 다시 씀(`--mp3-only` 로 강제 가능).
- `--webp`: 복사본의 큰 PNG를 WebP(q90, 알파 무손실)로 바꿔 40% 이상 줄 때만 교체 + 복사본 매니페스트 경로 수정(`webp_assets.py`, python3 + Pillow 필요, 원본 `assets/` 는 안 바뀜). README 기준 첫 로딩 약 12 MB → 9 MB.
- `--inline`(대비책, 출력 `dist/artifact_inline/`): 출처가 없는(opaque origin) 샌드박스 + CORS 없는 호스트에서는 Phaser 의 XHR 로딩이 전부 막힙니다. 그래서 모든 에셋을 `packs/assets_N.js`(약 4 MB씩, 이미지 = data URI, JSON = 객체, 오디오 = base64 mp3)에 넣고, `inline_loader.js` 가 Phaser `FileTypesManager` 의 json/image/spritesheet/atlas/audio 로더를 가로채서 XHR 없이 읽게 합니다. 용량은 +33%(base64) 늘어납니다. 서버 없이 `index.html` 더블클릭으로도 열립니다. 현재 8개 파일, 약 16 MB.
- 현재 일반 빌드 결과(웹p 없이): 파일 168개(ogg 41 + mp3 41 포함), 약 15 MB.

### 10.2 `test_deploy.mjs` (277줄) — 실제 호스팅 흉내
```
node tools/build/build_artifact.mjs            # 먼저 빌드 (sandbox-inline 은 --inline 빌드)
node tools/build/test_deploy.mjs [mode ...] [--quick]
```
| 모드 | 흉내 내는 환경 |
|---|---|
| `pages` | 저장소 전체를 GitHub Pages 처럼 `/nurient/` 아래 서빙하고 `/nurient/frost-village`(끝 슬래시 없이 → 301) 열기 — 절대 경로가 없는지 증명. **새 저장소에서는 `'/nurient/'` 와 `'frost-village'` 두 문자열을 바꿔야 함**(`testMode` 안) |
| `standalone` | dist/artifact 를 호스트 뼈대로 감싸서 직접 열기 |
| `sandbox` | 다른 출처 iframe `sandbox="allow-scripts"`(출처 없음) + 엄격한 CSP + CORS 없음 — **최악의 경우, 일반 빌드로는 실패가 정상**이라 기본 실행에서 빠짐 |
| `sandbox-cors` | 위와 같되 파일 서버가 `Access-Control-Allow-Origin: *` |
| `sameorigin` | iframe `sandbox="allow-scripts allow-same-origin"` + CSP (아티팩트가 자기 출처를 가지는 경우 — XHR·localStorage 동작) |
| `raw` | 본문만 있는 index.html 을 그대로(quirks mode) 서빙 — 예: `npx serve` |
| `sandbox-inline` | sandbox 와 같은 조건에서 `--inline` 빌드 |

모든 모드에서 확인하는 것: 부팅 → 타이틀(필수 텍스처·오디오 로드, 대체 그림 0) → 탭 → 마을 → 늦게 불러오는 음악·환경음 → 오디오 잠금 해제 → 첫 루프(그물 → 그릴 → 판매대 → 결제 → 동전, `--quick` 이면 그물까지만) → 저장 후 새로고침(localStorage 되는 환경에서만 유지 기대) → 페이지/콘솔 오류 0, 실패한 요청 0. 스크린샷 `dist/deploy_test/<mode>_*.jpg`. 모두 통과하면 exit 0. 전체 실행 약 15~25분(README).
흉내 CSP: `default-src 'self'; script-src 'self' https://cdnjs.cloudflare.com https://cdn.jsdelivr.net https://unpkg.com 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' data: blob:; connect-src 'self'; style-src 'self' 'unsafe-inline'`.
`test_deploy.mjs` 는 `../test/pw.mjs` 를 import 하므로 `tools/test/` 와 함께 복사해야 합니다.

### 13.2 지도 = 칸(타일) 격자
- 칸 한 변 = **√2 m** → 화면에서 **128×64 px 마름모**, 정수 픽셀(문서 03 §11.0과 같은 값. 현재 투영 `AX` × √2 = (64, 32)).
  ```js
  // src/core/Grid.js — 칸 (i, j): i = 월드 X(화면 오른쪽 아래), j = 월드 Y(화면 오른쪽 위)
  export const TW = 128, TH = 64;
  export function tileToScreen(i, j, o) { return { x: o.x + (i + j) * (TW / 2), y: o.y + (i - j) * (TH / 2) }; }
  export function screenToTile(x, y, o) {           // 마름모 칸 고르기: i, j 를 각각 반올림하면 정확
    const a = (x - o.x) / (TW / 2), b = (y - o.y) / (TH / 2);
    return { i: Math.round((a + b) / 2), j: Math.round((a - b) / 2) };
  }
  // 확인: (1,0) → (+64,+32), (0,1) → (+64,−32) — Iso.js 의 AX·AY 에 √2 를 곱한 값과 같음
  ```
- N×N 지도는 화면에서 마름모(가로 128N, 세로 64N px)로 보입니다. 화면에서 직사각형 모양 지도를 원하면 바깥 칸을 바다·절벽(지나갈 수 없음)으로 채우세요.
- 지도 데이터는 **층별 typed array**(칸 인덱스 `k = j * N + i`): `terrain`(Uint8, 지형 종류), `object`(Uint16, 나무·바위·건물 id), `owner`(Uint8, 영토), `road`(Uint8, 4방향 비트), `flag`(Int16, 깃발 id 또는 -1), `blocked`(Uint8). 메모리와 저장이 작고 빠릅니다.
- 깊이(그리기 순서)는 전작처럼 **화면 y = 깊이**. 지도 세로가 64N px 이므로 N=128이면 8192 → `DEPTH.FLY`(30000)보다 작아서 그대로 됩니다.

  ```js
  export const BUILDINGS = {

                  work: { gather: 'tree', out: 'item_log', time: 18 } },

  };
  ```

- 놓을 수 있는지: 발자국 칸이 모두 내 영토이고 비어 있는지, 문 앞 칸(깃발 자리)이 비었거나 이미 깃발인지. 문 방향은 그림의 yaw 에 맞춥니다(문서 03: yaw 0 = 문이 화면 왼쪽 아래 → 깃발 = 발자국의 −j 쪽, yaw 90 = 오른쪽 아래 → +i 쪽).
- 놓기 미리보기: 칸마다 초록/빨강 마름모(문서 04 `pad()` 로 만드는 "여기 지을 수 있음" 표시) — 세틀러2처럼 깃발/작은/중간/큰/광산 크기 표시.
- 건설: 공사장이 **자재 요청**(13.5)과 **건설 일꾼 요청**을 냄 → 자재가 오면 진행 → 진행도에 따라 그림 `c0..c3` → 완성(같은 frameSize·anchor 라 프레임만 교체, 문서 03 §11.1). 망치질 = `impactFrame` 에 먼지·나뭇조각 + 소리(전작 `onImpact` 방식).

### 13.4 길·깃발·짐꾼 (세틀러2 방식)
- **깃발**(노드): `{id, k(칸), wares: [wareId...] (최대 8), roads: [roadId...] (최대 6)}`. **길**(간선): `{id, a, b, tiles: [k...], carrier}` — 깃발과 깃발 사이, 길 하나에 짐꾼 정확히 1명.
- 길 그리기: 깃발에서 시작해 칸을 이어 찍고 다른 깃발에서 끝냄. 길 칸은 `road` 비트로 막힘 없이 걷기 가능. 짐꾼 수를 늘리려면 중간에 깃발을 더 꽂아 길을 나눔(세틀러의 핵심 재미).
- **짐꾼 상태기계**: `IDLE`(길 가운데 대기) → 양 끝 깃발에 "이 길로 가야 하는 물건"이 있으면 `TO_FLAG` → `PICK` → `CARRY`(반대쪽으로) → `DROP`(반대 깃발이 꽉 찼으면 기다림 — 세틀러식 정체가 자연스럽게 생김) 또는 `DELIVER`(반대 끝이 목적지 건물의 깃발이면 건물 안으로). 위치는 `(roadId, 칸 인덱스, 0..1 진행)` 이라 **경로 찾기가 필요 없습니다**.
- **물건 경로표**: 깃발 그래프에서 목적지 깃발까지의 다음 길(next hop). 길이 바뀔 때만 `graphVersion` 을 올리고, 목적지별 다익스트라를 필요할 때 계산해서 캐시합니다(깃발 수백 개, 차수 ≤ 6 → 한 번에 수 ms 미만 예상, 미검증). 간선 비용 = 길 칸 수(+ 깃발 혼잡도 가중치는 나중에).
- 깃발 위 물건은 `ItemStack`(전작)으로 작은 더미 그리기. 짐꾼 손의 물건은 `Character.carryOffset()` 규칙(머리 위 또는 carryPoint, NE·N은 몸 뒤)으로 1개만.

### 13.5 물건과 요청 연결 (물류)
- 물건(ware): `{id, type, at: ['flag'|'building'|'carrier', id], dest: buildingId|null}`.
- 건물은 필요할 때 **요청**을 냅니다(입력 재고 < 목표, 공사 자재). 0.5~1초마다 "연결기"가 돌면서, 요청마다 가장 가까운 남는 물건(창고 재고, 목적지 없는 깃발 위 물건, 생산 건물 출구)을 **깃발 그래프 거리**로 찾아 예약합니다. 한 틱에 처리하는 개수에 상한을 두세요.
- 생산된 물건은 건물 깃발에 목적지 없이 놓이고, 요청이 없으면 가장 가까운 창고로 갑니다(세틀러 규칙).
- 운반 우선순위·물건 분배(예: 석탄을 어느 제련소에 먼저)는 데이터 표 + 설정 화면으로(나중).

### 13.6 직업과 도구
- 창고에 **일반 주민(짐꾼 후보)** 이 시간에 따라 생깁니다(`balance.population.spawnEvery`, 상한).
- 건물이 완성되면 그 직업의 일꾼을 요청합니다. 창고에 그 직업이 있으면 보내고, 없으면 `jobs.js` 의 도구가 창고에 있는지 봅니다. **도구 1개 + 일반 주민 1명 → 그 직업**으로 바꿉니다(도구가 직업을 연다). 도구 대장간이 도구를 만들고, 무엇을 먼저 만들지는 설정으로 정합니다.
  ```js
  export const JOBS = { carrier: { tool: null }, woodcutter: { tool: 'item_axe' }, carpenter: { tool: 'item_saw' },
                        miner: { tool: 'item_pickaxe' }, fisher: { tool: 'item_rod' }, builder: { tool: 'item_hammer' } };
  ```
- 일꾼은 창고에서 건물까지 **길을 따라** 걸어갑니다(경로표 재사용).

### 13.7 생산 사슬
- 전작 아이템 재사용: 통나무→판자, 밀→빵, 생선, 고기, 광석→주괴(+ 새로: 돌, 밀가루, 석탄, 금, 도구 6종 — 문서 03 §11.5, 문서 04 아이콘).
- 광산은 한 번 캘 때마다 음식 1개(`item_fish_cooked | item_bread | item_meat_cooked` 중 아무거나)를 씁니다. 음식이 없으면 멈추고 건물 위에 상태 말풍선을 띄웁니다. 이때 전작 이모티콘 `emote_bread`, `emote_fish`, `emote_zzz`, `emote_exclaim` 과 `ui_emote_bubble` 을 그대로 쓸 수 있습니다(`emotes` 폴더를 FRAGMENTS 에 연결).
- 생산 건물 상태: `NO_WORKER → WAIT_INPUT → WORKING(time) → OUTPUT_FULL`. 작업 중 `spr:<건물>:work` 루프 + 연기(`fxPoints.smoke`).
- 밸런스는 Node 시뮬레이션(13.12)으로 "분당 생산량, 병목 건물, 쌓이는 물건"을 표로 뽑아서 조정합니다.

### 13.8 영토
- 군사 건물(경비 초소, 탑…)마다 반경 `radius` 칸. 완성될 때 `owner` 층을 다시 계산합니다. 지도 크기가 128² 이하이면 원을 전부 다시 찍어도 충분히 빠릅니다(미검증, 측정 권장).
- 경계 칸(이웃 중 남의 영토가 있는 칸) 목록 → 경계 말뚝 소품(문서 03 §11.4)이나 `Graphics` 점선(문서 04)으로 표시. 건물은 내 영토 안에만 놓을 수 있습니다.
- 전투를 넣을지는 기획에서 정하세요. 넣지 않으면 영토는 늘어나기만 합니다.

### 13.9 경로 찾기 (A*)
- **대부분의 이동에는 경로 찾기가 필요 없습니다.** 짐꾼은 자기 길 위만, 일꾼의 출퇴근은 길 그래프(경로표)를 따릅니다.
- A* 는 길 밖으로 나가는 일꾼에게만 씁니다(나무꾼 → 반경 안 나무, 어부 → 물가, 지질학자, 군인). 반경이 작아서 탐색 범위도 작습니다.
- 구현 메모: 8방향(대각선 이동 시 모서리 끼어들기 금지), 옥타일 휴리스틱, 지도 크기 고정 버퍼 재사용(`Float32Array g`, `Int32Array parent`, `Uint32Array` 방문 도장 — 매번 지우지 않음), 이진 힙, 확장 노드 상한(예: 4000)을 넘으면 실패로 처리하고 그 목표를 잠시 피함(전작 Worker 의 "7초 못 가면 15초 피함"과 같은 발상). 오가는 길은 경로를 뒤집어 재사용.
- **일꾼끼리는 충돌시키지 않습니다**(세틀러 원작도 겹쳐 지나감). 전작 `moveAgent` 의 모든 agent 쌍 분리 계산(O(n²))이 군중 비용의 주된 원인으로 보입니다(13.10).

### 13.10 일꾼 수백 명을 위한 성능
**근거(전작 실측, 9.3)**: 지금 구조(캐릭터마다 스프라이트 + 그림자 + 짐 스프라이트들, 매 프레임 O(n²) 분리 + 충돌 밀어내기)로는 agent 116명 2.8 ms, 316명 10.6 ms, 616명 35 ms(Game 업데이트만, 헤드리스)였습니다. 300명만 넘어도 모바일 60fps 예산(16.7 ms)에서 로직이 큰 몫을 차지합니다. 반대로 그리기는 아틀라스 덕분에 프레임당 4~6회 그리기 호출로 가벼웠습니다.

권장 구조:
1. **고정 스텝 + 보간**
   ```js
   // scenes/Game.js (세틀러식)
   const TICK = 0.1;                                    // 시뮬레이션 1틱 = 0.1초 (10 Hz)
   update(time, delta) {
     this.acc += Math.min(delta / 1000, 0.25) * this.speed;   // speed: 1, 2, 4 (배속)
     let n = 0;
     while (this.acc >= TICK && n < 8) { this.sim.tick(TICK); this.acc -= TICK; n++; }
     if (n === 8) this.acc = 0;                          // 너무 밀리면 버림 (느린 기기에서 멈춤 방지)
     this.view.render(this.sim, this.acc / TICK);        // 0..1 사이 보간 비율
   }
   ```
   일꾼은 "칸 a → 칸 b, 진행 t" 로 움직이므로 그리기 위치 = `lerp(a, b, t + 속도·보간)`. 시뮬레이션 갱신이 60회에서 10회로 줄어듭니다.
2. **시뮬레이션 객체 ≠ Phaser 객체.** 일꾼은 숫자 몇 개짜리 일반 객체(또는 typed array 묶음)입니다. 화면에 보이는 일꾼에게만 **풀에서 스프라이트를 빌려 줍니다**(`EntityView`: 카메라 `worldView` + 여유 안에 있는 일꾼 → 스프라이트 배정, 벗어나면 반납). Phaser 3 는 일반 스프라이트를 화면 밖이라고 자동으로 빼 주지 않습니다. 카메라 렌더는 `willRender`(보임·알파)만 확인하고, 경계 컬링은 타일맵 레이어에만 있습니다(phaser.min.js 3.90 코드에서 확인). 그래서 컬링은 직접 해야 합니다. 나무·바위 같은 정적 물건도 청크 단위로 `setVisible(false)` 하세요.
3. **애니 갱신 최소화**: `play()` 는 애니·방향이 바뀔 때만 호출하세요(`Character.play` 가 이미 같은 키면 바로 돌아감). 멀리 줌아웃(예: 줌 < 0.6)하면 그림자·손에 든 물건 숨기기, 애니 정지(LOD).
4. **트윈 대신 계산**: 수백 개 물건 이동에 `Effects.fly`(물건마다 트윈)를 쓰지 말고, 시뮬레이션 위치에서 그리세요. 연출용 짧은 효과에만 트윈을 쓰세요.
5. **글자**: 자주 바뀌는 숫자(재고, 인구)는 `BitmapText` 로. `Text` 는 바뀔 때마다 캔버스를 다시 그리고 GPU로 올립니다(9.3 측정). 숫자·기호만 담은 비트맵 폰트는 Pillow 로 만들 수 있습니다(문서 04 도구 방식, 미검증).
6. **텍스처 예산**: 캐릭터 아틀라스 하나가 약 0.8~1.3 Mpx(GPU에서 약 3~5 MB)였습니다. 직업이 15~20개면 직업별 애니를 최소로 하세요. 짐꾼은 idle·walk·carry_idle·carry_walk 정도만(약 120프레임) 두는 식입니다. 깊이 순서로 섞여 그려지므로 동시에 보이는 텍스처 종류가 GPU 텍스처 유닛 수(기기마다 다름)를 넘으면 그리기 호출이 늘어납니다. `review_robust_drawcalls.mjs` 로 측정하세요.
7. **큰 지도 바닥**: 전작처럼 지도 전체를 한 번에 굽는 방식은 큰 지도에서 메모리가 부족합니다(예: 64×64칸 = 8192×4096 px 경계 = 33 Mpx ≈ 134 MB). 대신 **1024×1024 청크를 화면 근처만 굽고 LRU 로 10~16장 유지**하세요(`Ground.js` 의 굽기 함수 재사용). 길을 놓으면 그 청크만 다시 굽습니다(전작의 부드러운 길 기법). 다른 방법으로 Phaser 아이소 타일맵이 있습니다. 3.90 에 `Orientation.ISOMETRIC` 이 있지만, 빈 `make.tilemap()` 은 직교형이라 Tiled 형식 JSON(`orientation: "isometric"`)을 만들어 넣어야 합니다. 이 방법은 미검증이라 첫 주에 시제품으로 확인하세요.
8. **측정 루틴**: `?debug=1` 의 FPS·objs, `review_robust_crowd.mjs` 를 고쳐서 "일꾼 100/300/600/1000명 주입 → 틱 ms·렌더 ms" 를 매 단계 기록하세요. 목표 예시: 중급 폰에서 일꾼 500명, 시뮬레이션 틱 < 4 ms(10 Hz라 프레임당 평균 < 1 ms), 렌더 < 8 ms.

### 13.11 입력과 카메라
- 아바타가 없으므로: 한 손가락 끌기 = 카메라 이동(관성), 두 손가락 = 핀치 줌(Phaser 내장 없음 → 두 포인터 거리 비율로 직접. `activePointers: 3` 은 이미 설정), 탭 = 선택(칸 고르기는 `screenToTile` 을 카메라 좌표에 적용), 길게 누르기 = 정보. PC는 끌기 + 휠 줌 + WASD 이동.
- 카메라 줌 범위 예: 0.5~1.4(`setZoom(zoom * View.k)`). 캐릭터는 줌 1에서 약 80 px, 0.6 에서 약 48 px — 작게 많이 보이는 세틀러 느낌은 **그림을 다시 렌더하지 말고 줌으로 먼저 시험**하세요(문서 03 §10.5).
- 메뉴(건물 목록, 재고, 통계)가 길고 스크롤이 필요하면 Phaser 에는 위젯이 없습니다. 방법은 두 가지입니다. (a) 전작 UI 장면처럼 직접 그리기(`panel()` 9-slice + 마스크 스크롤). (b) 캔버스 위 DOM 오버레이(HTML/CSS, 한글 선명, 기본 스크롤). (b)는 아티팩트에서도 동작합니다(일반 HTML). 다만 스타일을 `ui_panel`(크림 `#FFF8EC`, 글자 `#2B2F3A`)과 맞추고, 테스트는 DOM 선택자로 하세요.
- **세로 vs 가로**: 전작은 세로 전용입니다(`#fv-rotate`, webmanifest `portrait`, 논리 가로 720 고정). 세틀러식은 넓은 지도에 가로가 어울릴 수 있으니 기획 단계에서 정하고, 정해지면 `main.js` 의 `logicalHeight/updateView`, `index.html` 회전 안내 조건, `manifest.webmanifest` 의 `orientation` 을 함께 바꾸세요.

### 13.12 시뮬레이션 시험 (Node, 브라우저 없이)
